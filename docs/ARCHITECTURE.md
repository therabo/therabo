# Architecture

Generation and playback are separate: Node.js validates public data and compiles
self-contained SVG markup/CSS/SMIL. GitHub displays the generated image without
running JavaScript. There are no runtime package dependencies.

| Responsibility | Owner |
|---|---|
| Public calendar acquisition/validation | `contribution-calendar.mjs` |
| Public activity acquisition and cards | `build-activity-card.mjs`, `graphics.mjs` |
| Account-history streak collection/calculation | `activity-streaks.mjs` (reuses calendar validation) |
| Dataset mode selection and build configuration | `invaders.mjs` |
| Calendar geometry/colors/canonical sequence | `contribution-scene.mjs` |
| Shared canvas, bounds and directional envelopes | `motion-geometry.mjs` |
| Seeded random streams | `random.mjs` |
| Full-set placement and certification | `organic-deployment.mjs`, `deployment-routes.mjs` |
| Representative selection/readability | `horde-selection.mjs` |
| Individual invader motion | `horde.mjs` |
| Invader composition and rendered clock | `invader-scene.mjs`, `invader-timing.mjs` |
| Shared starfield/projectile artwork | `space-visuals.mjs` |
| Shared ship/trail geometry and pose | `ship.mjs` |
| Target selection, intercept and lifecycle | `gameplay.mjs` |
| Hit effects and victory lettering | `hit-explosion.mjs`, `invader-ending.mjs` |
| Native hidden reset and replay | `simple-reset.mjs` |
| Meteor composition, spawning and evasion | `meteor-scene.mjs`, `meteor-dodge.mjs` |

Mode selection happens once at the build/render boundary. Ending an Invader game
cannot select Meteor Mode. Shared artwork accepts explicit timing/flight inputs;
Meteor planning imports no Invader gameplay or shooting module.

Activity obtains the existing public REST/search metrics and the account creation
date, then collects anonymous calendar years through today in UTC. The streak
module reuses `fromPublicHTML`/`normalizeCalendar` without changing the game
collector. Complete coverage is required before calculation or output writes.
Its schema-v2 snapshot adds current/longest counts, ranges, history scope and
as-of date to the existing metrics. All four Activity SVGs share that snapshot;
desktop divides metrics/streaks left/right, mobile stacks them in the same frame.
The workflow and output file contract are unchanged. See ADR-0006.

The canonical clock is preserved to keep sampled ship/trail paths, intercepts and
motion phases stable. `invader-timing.mjs` composes the 2× morph clock, 40% retained
pre-positioning gap and 1.60× positioning clock. Later events translate by saved
time; gameplay speed does not change. Ending derives from the last real explosion,
and reset derives from ending. The replay adapter receives that same clock.
Meteor owns its fixed unified intro and perpetual schedule independently.

Geometry belongs to its domain, not a global constants bag. Canvas dimensions are
shared; art dimensions and logical projectile hit dimensions deliberately differ.
The two seed hashes are also intentionally different: SHA for layout/space and FNV
for approved individual motion. Their shared PRNG step does not change draw order.

The dependency graph is acyclic. Scene composition has the highest coupling by
design; geometry and randomness are lightweight leaves. Placement strategies that
look historical remain live fallback paths and protect full-set incumbents.

Tests are separated from production modules. Review HTML, image comparisons,
search reports and build logs do not belong in the repository. Golden fixtures
are retained only where they protect a reusable safety/readability invariant.
Maintenance refactors must preserve deterministic generated bytes; playback checks
also use SVG-as-image with JavaScript disabled, including a second full cycle.
